# Карта вселенной «Основания» — дизайн v1

Дата: 2026-09-29. Статус: черновик на ревью владельца (после прохода трёх критиков).
Разведка стека: [../../research/2026-09-29-3d-stack-research.md](../../research/2026-09-29-3d-stack-research.md).

## 1. Что делаем и зачем

Публичная интерактивная 3D-карта вселенной «Основания»: сериал Apple TV+ (сезоны 1–3, 2021–2025) как основа, оригинальная трилогия Азимова («Основание», «Основание и Империя», «Второе Основание») как слой расхождений.

Две цели:
- публикация для русскоязычных зрителей и читателей;
- памятка владельцу: «кто, где, когда» через 400 лет скачков во времени.

Адрес: `https://atlonis.github.io/foundation/`. Код живёт в папке `foundation/` монорепо `lab`.

## 2. Решения брейншторма (в v1 не пересматриваем)

| Вопрос | Решение | Почему |
|---|---|---|
| Канон | Сериал — позвоночник, книга — слой «в книге иначе» на карточке | В трилогии нет сквозных героев; сериал смотрели вдвоём |
| Ось навигации | Таймлайн по эрам. Эра — только отрезок времени, не сюжетная линия | Главная путаница «Основания» — скачки на 100+ лет |
| Язык | Русский, оригинальные имена в скобках; данные готовы к английскому | По-русски связной карты «сериал против книги» нет |
| Спойлеры | Фильтра нет, баннер «спойлеры на 3 сезона и 3 книги»; сезон и книга остаются в данных | Фильтр добавляется потом за полчаса |
| Подача | 3D, концепт «Нить Первичного Излучателя» | Прямая цитата сериала; время и пространство не путаются |
| Стек | React Three Fiber 9.8 + drei 10.7, three r186, WebGLRenderer, Vite 8, TypeScript | Владелец React-разработчик; drei даёт нужные примитивы; WebGPU-ветка экосистемы ещё в альфе |
| Хостинг | GitHub Pages через монорепо `lab` | Уже работает |

## 3. Сценарии

1. **Зритель после сезона.** Открывает, скроллит нить эр, у каждой остановки видит планеты и маркеры людей эры, тапает по маркеру, читает карточку.
2. **Читатель книги.** Открывает персонажа, переключает вкладку «В книге»: пол, роль, судьба, чего в книге нет вовсе.
3. **Владелец вспоминает.** Режим «Список»: плоский таймлайн со всеми карточками, без 3D, читается как конспект.
4. **Телефон в метро.** Тап по планете — снизу выезжает карточка; кнопка «Показать на карте» — камера подлетает. Батарея не горит: кадры рисуются только при движении.

## 4. Концепт и режимы

Одна 3D-галактика с ~20 именованными планетами. Над диском висит светящаяся спираль — нить Плана Селдона. Витки нити — эры, узлы на витке — события и кризисы.

**Режим «Хроника»** (по умолчанию). Скролл или свайп ведёт камеру вдоль нити. Остановки — эры (5, см. 5.4). На остановке камера наклоняется к диску, планеты и маркеры персонажей эры подсвечиваются, остальные планеты гаснут до 15 % яркости. Палитра сцены плавно меняется по эре: Империя — золото, Основание — холодный синий, Мул — красный, Второе Основание — фиолетовый. Тап по планете или маркеру персонажа открывает карточку и подсвечивает объект; **камера в «Хронике» при тапе не двигается** — остановки эр подобраны так, что планеты эры лежат в верхних 45 % кадра (проверяется на телефоне при подборе ракурсов). Подлёт к планете есть только в «Карте»; в карточке кнопка «Показать на карте» переключает режим и делает подлёт.

**Режим «Карта».** Свободный облёт галактики (drei `CameraControls`), чипы эр сверху. Выбор эры гасит неактуальные планеты и ставит камеру на сохранённый ракурс эры. Клик по планете — плавный подлёт (`setLookAt` с переходом) и карточка.

**Режим «Список».** Обычный DOM: эры как секции, внутри карточки планет, персонажей, фракций, событий, объектов. Тот же JSON. Это и fallback без WebGL2, и путь при `prefers-reduced-motion`, и режим чтения для памятки.

Переход между режимами сохраняет выбранную эру и открытую сущность (они в URL, см. 6.2).

## 5. Данные

### 5.1 Сущности

Семь видов: `era`, `planet`, `character`, `faction`, `event`, `artifact`, `difference`.

- **era** — отрезок таймлайна: годы, палитра, порядок на нити. Эры не пересекаются по годам.
- **planet** — мир: положение в галактике (полярные координаты), процедурный облик, эры, в которых важен.
- **character** — персонаж: фракция и родной мир по умолчанию, актёр, состояние по эрам.
- **faction** — Империя, Основание, Второе Основание, Анакреон, торговцы, Мул и т. п. Сюжетные линии живут здесь и присутствуют в нескольких эрах.
- **event** — событие или кризис Селдона: год, планета, эра.
- **artifact** — объект или место, которое не планета: Хранилище, Первичный Излучатель, «Инвиктус», Звёздный мост. В 3D не рисуется, живёт в «Списке» и во «Связях» планеты.
- **difference** — сквозное расхождение книги и сериала («генетическая династия Клеонов — изобретение сериала») со ссылками на затронутые сущности.

Расхождение на уровне одной сущности живёт внутри неё, в блоке `book`. Вид `difference` только для сквозных тем, которые нельзя приписать одной карточке.

**Правило для блока `book`.** Блок обязателен у всех видов, кроме `era`. `presence` считается относительно трилогии. Для сущностей из приквелов и сиквелов (Демерзель, Клеон I) ставим `show-only` и первой строкой `diff` пишем: «В трилогии нет; у Азимова есть в «Прелюдии к Основанию»».

**Правило для генетической династии.** Три карточки-титула `brother-day`, `brother-dusk`, `brother-dawn` с фиксированными актёрами; в `timeline` каждой эры записано, какой Клеон носит титул. Отдельные карточки только у Клеонов с личной аркой (Клеон I, Рассвет XIV из S1, День XVII из S2, ключевые Клеоны S3 — список уточняется в контент-фазе). У титульной карточки `related` → эти персоны с ролью «носил титул». Сквозное расхождение «династия — изобретение сериала» остаётся видом `difference`.

### 5.2 Шкала времени

Единая шкала — годы Эры Основания (Э.О., в книге F.E.). Год 0 Э.О. = суд над Селдоном = 12 067 И.Э. сериала (в книге отсчёт Э.О. идёт с 12 067–12 069 Г.Э., расхождение в 1–2 года игнорируем). Константа `FE_ZERO_IE = 12067` в `derive.ts`; на карточке события обе даты: «35 Э.О. (12 102 И.Э.)». Опорные точки сериала: S1 — 0 и ~35 Э.О.; S2 — ~173 Э.О. (+138 лет); S3 — ~325 Э.О. (+152 года). Точные значения проверяются в контент-фазе.

Одни и те же события в сериале и книге датированы по-разному (первый кризис Хардина: ~35 Э.О. в сериале, 50 в книге). Поэтому у события и эры есть второе, книжное, поле года.

Эры — непересекающиеся отрезки Э.О. `build-data` проверяет, что `years.start/end` идут по возрастанию `order` без перекрытий, и что `event.year` (если задан) попадает в отрезок одной из его `eras`.

### 5.3 Схема

```ts
type Text = { ru: string; en?: string };
type View = { position: [number, number, number]; target: [number, number, number] };
// view хранит десктопный ракурс (объект в центре кадра). На телефоне тот же view,
// target смещается вниз через CameraControls.setFocalOffset, чтобы объект встал
// в верхнюю треть экрана над bottom sheet.

type BookPart =
  | 'psychohistorians' | 'encyclopedists' | 'mayors' | 'traders' | 'merchant-princes'  // кн. 1
  | 'general' | 'mule'                                                                 // кн. 2
  | 'search-by-mule' | 'search-by-foundation';                                        // кн. 3
// номер книги выводится из части в derive.ts; SEASONS = 3 — константа в одном месте,
// баннер и валидация читают её (zod: season — целое 1..SEASONS+1, чтобы S4 не ломал типы)

type Kind = 'era' | 'planet' | 'character' | 'faction' | 'event' | 'artifact' | 'difference';

interface Base {
  id: string;                       // kebab-case, уникален среди всех видов
  kind: Kind;
  name: Text;                       // «Салвор Хардин»
  originalName?: string;            // "Salvor Hardin"
  summary: Text;                    // 1–2 предложения, для списка и hover
  body?: Text;                      // markdown; основной текст карточки
  eras: string[];                   // id эр, где сущность активна
  appearsIn: {
    show?: { season: number; episodes?: number[] }[];
    book?: BookPart[];
  };
  timeline?: {                      // состояние по эрам; несколько записей на эру допустимы
    era: string;                    // обязан входить в eras
    note: Text;                     // «Цифровая копия в Хранилище на Терминусе»
    status?: 'alive' | 'dead' | 'digital' | 'cryo' | 'destroyed' | 'absent';
    planet?: string;                // где находится в эту эру
    faction?: string;               // чью сторону держит в эту эру
  }[];
  book: {                           // обязателен у всех, кроме era
    presence: 'same' | 'different' | 'show-only' | 'book-only';
    diff?: Text;                    // markdown, вкладка «В книге»
    name?: Text;                    // имя в книге, если отличается: «Байта Дарелл»
    originalName?: string;          // "Bayta Darell"
    counterpart?: string;           // id отдельной карточки-двойника, если в книге это другой персонаж
  };
  related: { id: string; role: Text }[];   // «дочь», «правит», «родной мир»
  sources: string[];                // URL: вики, страницы эпизодов
}

interface Era extends Omit<Base, 'eras' | 'book'> {
  kind: 'era';
  order: number;                    // позиция на нити, 1..N
  years: { start: number; end: number; bookStart?: number; bookEnd?: number; label: Text };
  palette: { primary: string; glow: string };
  view?: View;                      // ракурс эры в режиме «Карта»
}

interface Planet extends Base {
  kind: 'planet';
  galaxy: { arm: number; r: number; offset: number; y?: number };  // r в [0,1] от центра
  look: { type: 'city' | 'ocean' | 'desert' | 'ice' | 'gas' | 'barren'; colorA: string; colorB: string; radius: number };
  // рендер — один инстансированный шейдер, см. 6.3
  view?: View;
}

interface Character extends Base { kind: 'character'; faction?: string; homeworld?: string; actor?: string; }
interface Faction   extends Base { kind: 'faction'; color: string; }
interface Event extends Base {
  kind: 'event';
  year?: number;                    // Э.О. по сериалу; для book-only — по книге
  yearBook?: number;                // Э.О. по книге, если событие есть в обоих и датировано иначе
  yearLabel?: Text;                 // «между S1 и S2», когда точного года нет
  planet?: string;
  isSeldonCrisis?: boolean;
}
interface Artifact  extends Base { kind: 'artifact'; planet?: string; }
interface Difference extends Base { kind: 'difference'; }
```

Проверки `build-data` сверх zod: уникальность `id`; существование всех ссылок (`related[].id`, `eras`, `faction`, `homeworld`, `planet`, `timeline[].planet/faction`, `book.counterpart`); `timeline[].era ∈ eras`; у `event` задан хотя бы один из `year` / `yearLabel`; эры не пересекаются и идут по `order`; `event.year` внутри отрезка одной из его эр.

### 5.4 Предварительный список эр

Хронологический; годы Э.О., 0 = суд над Селдоном. Состав и датировки уточняются в контент-фазе, структура — нет.

1. **Трантор: суд и ссылка** — 0 Э.О. (S1, начало; кн. 1 «Психоисторики»). Селдон, Гаал, Демерзель, Клеоны, Звёздный мост.
2. **Терминус: Хардин и Анакреон** — ~35 Э.О. в сериале / 50–80 Э.О. в книге (S1, остальное; кн. 1 «Энциклопедисты», «Мэры»). Параллельно имперская линия на Транторе.
3. **Торговцы, генерал, второй кризис** — ~173 Э.О. в сериале / 135–195 Э.О. в книге (S2; кн. 1 «Торговцы», «Князья торговли»; кн. 2 «Генерал»). Мэллоу, Бел Риоз, Клеон XVII, Второе Основание на Игнисе (только сериал).
4. **Мул** — ~325 Э.О. в сериале / 300–316 Э.О. в книге (S3; кн. 2 «Мул», кн. 3 «Поиски Мула»). Калган, Байта и Торан, Эблинг Мис, Причер.
5. **Поиски Второго Основания** — ~376 Э.О., только книга (кн. 3 «Поиски Основания»). Аркади Дарелл, Прим Палвер.

Великое разграбление Трантора (только книга) — `event` между эрами 3 и 4, не эра. Отдельной эры «Империя между сезонами» нет: имперская линия — это `faction` Империя и Трантор в `eras` каждой эры.

### 5.5 Хранение и сборка данных

- Контент — по файлу на сущность: `foundation/content/<kind>/<id>.yaml`. Удобно агентам писать, владельцу ревьюить, гиту диффать.
- `scripts/build-data.ts` собирает всё в один `public/data/foundation.json`: валидирует схему (zod) и проверки из 5.3, считает производные (`xyz` планет из полярных координат, `t` каждой эры на нити, номер книги из `BookPart`), падает на любой ошибке. Запускается перед `vite build`.
- Объём v1: 5 эр, ~20 планет, ~40 персонажей (~30 из сериала, ~10 только книжных), ~8 фракций, ~30 событий, ~6 объектов, ~15 расхождений. Около 125 карточек.
- У каждой карточки есть `sources`. Факты, от которых зависит структура (эры, принадлежность к сезону и книге, расхождения), проходят отдельную проверку в контент-фазе.
- Картинок нет: стиллы из сериала под авторским правом, а сайт публичный. Планеты рисуются процедурно, персонажи — текстом и маркером цвета фракции.

## 6. Архитектура фронтенда

### 6.1 Стек и версии

Пиним точно, коммитим `package-lock.json`, не обновляем до конца v1:

- `three` 0.186.x, `@react-three/fiber` 9.8.x, `@react-three/drei` 10.7.x (только `CameraControls`, `ScrollControls`, `Text`, `Html`), `react` 19.2.x
- `zustand` для состояния, `gsap` 3.15 для твинов
- `zod`, `yaml`, `vite` 8, `typescript`, `vitest`, `tsx` (запускает `build-data`), `@playwright/test`, `size-limit`, `rollup-plugin-visualizer`
- Шрифт: Inter, один и тот же для UI и troika `Text`; self-hosted `.woff` с сабсетом Latin + Cyrillic + Cyrillic-ext + «»—…ёЁ (~100 КБ). troika не читает `.woff2`.

Не берём: R3F 10 и drei 11 (альфа), `@react-three/postprocessing` в v1, Theatre.js (заморожен), WebGPURenderer (отдельный эксперимент позже).

### 6.2 Структура, данные, маршруты

```
foundation/
  content/<kind>/<id>.yaml
  public/data/foundation.json      # собирается, в git не коммитим
  public/fonts/inter-cyr.woff
  public/poster.webp
  scripts/build-data.ts
  src/
    main.tsx, App.tsx
    data/   schema.ts (zod + типы), load.ts, derive.ts (чистая математика: xyz, спираль)
    state/  store.ts (zustand: mode, eraId, selectedId, tier)
    router/ hash.ts
    scene/  Scene.tsx, GalaxyLayer.tsx, Dust.tsx, Planets.tsx, CharacterMarkers.tsx, Thread.tsx,
            CameraRig.tsx, Labels.tsx, palette.ts
    ui/     EntityCard.tsx, EraNav.tsx, ModeToggle.tsx, SpoilerBanner.tsx,
            ListView.tsx, Loading.tsx
  docs/
```

**Поток данных.** `foundation.json` → `load.ts` (fetch + проверка версии и формы; полная zod-валидация только в `build-data`, чтобы zod не попадал в оболочку) → `store` → сцена и UI читают один и тот же стор. Сцена никогда не хранит контент, только id.

**Два чанка.** Оболочка (react, react-dom, zustand, роутер, «Список», карточка) не импортирует `three`, `@react-three/*`, `gsap`. 3D-чанк грузится динамическим `import()`. Все пути к `public/` — только через `import.meta.env.BASE_URL`: абсолютные `/data/...` под `/foundation/` дают 404, а troika при недоступном шрифте молча тянет Roboto с CDN (проверять в Network, что запросов к внешним CDN нет).

**Где считается геометрия.** `src/data/derive.ts` — чистая математика без импорта `three` (иначе three попадает в оболочку). Экспортирует `planetXYZ(galaxy)` (полярные → xyz тем же спиральным правилом, что и галактика) и аналитическую спираль `helix(t): [x, y, z]`, `t ∈ [0, 1]`: `angle = t · turns · 2π`, `radius = r0 + (r1 − r0) · t`, `y = h0 + (h1 − h0) · t`; константы `turns, r0, r1, h0, h1` подбираются в каркасе. Эра с `order = i` стоит на `t_i = (i − 1) / (N − 1)` — монотонность гарантирована конструкцией. `build-data` пишет `xyz` планет и `t` эр в JSON. `Thread.tsx` строит `CatmullRomCurve3` из 200 сэмплов `helix()` только для `TubeGeometry`; `CameraRig` берёт позицию как `helix(offset)` напрямую, `getPointAt` не используется, иначе `t` эры и арк-длина разойдутся. Точки галактики, пыли и фона генерируются в рантайме функцией `buildGalaxy(seed, count)` с константным сидом (mulberry32) и в JSON не попадают.

**Маршруты.** Грамматика: `#/<mode>/<eraId>[/<kind>/<id>]`, `mode ∈ {chronicle, map, list}`. Примеры: `#/chronicle/terminus-crisis`, `#/map/mule/character/bayta`, `#/list/trantor-trial`. Режим — сегмент хэша, не `?mode=`: смена query перезагружает страницу. Источник истины — URL: `hash.ts` парсит его в стор при старте и на `hashchange`; изменения стора пишутся в URL: смена эры и режима — `replaceState`, открытие карточки — `pushState` (кнопка «Назад» закрывает карточку). Открытие сущности, у которой нет активной эры в `eras`, переключает эру на первую из `entity.eras`. Пустой, неизвестный хэш или несуществующий id → `#/chronicle/<первая эра по order>` и тост «Такой страницы нет».

### 6.3 Сцена, слои и бюджет

| Слой | Реализация | Draw calls |
|---|---|---|
| Фон-звёзды | `Points`, 15–20k точек на сфере, статичные | 1 |
| Галактика | `Points` с шейдером: спиральные рукава, плотность к центру, мягкая точка вместо bloom, медленное дифференциальное вращение через `uTime`. Детерминированный сид | 1 |
| Пыль и ядро | второй `Points` вдоль рукавов + 1–2 аддитивных `Sprite` | 2–3 |
| Планеты | один `InstancedMesh` (SphereGeometry 24×16) с кастомным `ShaderMaterial`; per-instance атрибуты `aColorA`, `aColorB`, `aType` (0–5 по `look.type`), `aDim` (0–1, гашение вне эры); облик — 2 октавы value-noise, маска по `aType` (полосы / пятна / сплошной); освещение фиксированным направленным светом прямо в шейдере (half-lambert + rim), объектов `Light` в сцене нет. Невидимые прокси-сферы для пикинга радиусом ≥ 24 px экрана: `visible={false}` с `onClick` — three не проверяет `visible` при рейкасте, R3F рейкастит только объекты с обработчиками, draw calls прокси не дают | 1 |
| Маркеры персонажей | один `Points` с текстурой-диском, per-instance цвет фракции (`timeline[era].faction ?? faction`); только персонажи активной эры, ≤ 12 видимых; позиция — дуга над планетой из `timeline[era].planet ?? homeworld`, порядок по `id`; если планеты нет — над узлом эры на нити. Пикинг — прокси-сферы, как у планет | 1 |
| Нить | спираль из `helix()`, тонкая `TubeGeometry` с аддитивным материалом (1); узлы эр — один `Points` с текстурой-спрайтом (1); события — второй `Points` (1) | 3 |
| Подписи | troika `Text`, ≤ 20 видимых: в «Хронике» планеты активной эры + подпись эры, остальные `fillOpacity 0` (твин 0.4 с); в «Карте» планеты выбранной эры + ближайшие к камере до 20 | ≤ 20 |
| Подсветка выбранного | кольцо-спрайт, анимация появления 0.6 с, дальше статично | 1 |

Итого на телефоне ≤ 31 draw calls, на десктопе ≤ 100. Точки галактики ≤ 8 px экрана: аддитивный overdraw — главный убийца fill-rate. Запасной вариант, если шейдер планет не готов к концу этапа 2: `look` сокращается до `{ color, radius }`, поля `type` и `colorB` удаляются из схемы, а не остаются мёртвыми.

**Тап-цели в 3D** — только планеты и маркеры персонажей. Карточка эры открывается чипом EraNav; события, фракции и объекты — из вкладки «Связи» открытой карточки и из «Списка».

**Камера. Владелец один.** В каждый момент камерой владеет ровно один компонент: в «Хронике» — `CameraRig` (пишет `camera.position` и `lookAt` из `scroll.offset`), в «Карте» — drei `<CameraControls makeDefault>`. `<ScrollControls>` и `<CameraControls>` никогда не смонтированы одновременно: `enabled={false}` не спасает, drei зовёт `controls.update(delta)` каждый кадр, а camera-controls безусловно перезаписывает `camera.position`. GSAP камеру не двигает.

- Хроника → Карта: размонтировать `ScrollControls`; смонтировать `CameraControls`; в эффекте монтирования `setLookAt(текущая поза, false)`, затем `smoothTime = 1.2; setLookAt(view эры, true)`.
- Карта → Хроника: сохранить `getPosition()/getTarget()` в стор, размонтировать `CameraControls`; `CameraRig` 1.2 с лерпит от сохранённой позы к `helix(t(era))` через `gsap.to(progress, …, onUpdate: invalidate)`, по завершении ставит `scroll.el.scrollTop` на эру и отдаёт управление скроллу.
- Клик по планете в «Карте» — `setLookAt(view планеты, true)` со `smoothTime 1.2`. На телефоне дополнительно `setFocalOffset`, чтобы планета встала в верхнюю треть над карточкой.

**Активная эра и остановки «Хроники».** Единица «виток» ниже — шаг между остановками `spacing = 1/(N−1)`. `ScrollControls` не снапит, поэтому: активная эра = эра ближайшей остановки по `t` с гистерезисом 0.1 витка. Скролл свободный; через 150 мс без scroll-событий, если |t − t_эры| < 0.3 витка, `scroll.offset` дотягивается к остановке GSAP-твином 0.4 с (твиним offset, не камеру). Клик по чипу EraNav и заход по URL — тот же твин offset за 0.8 с. Палитра и гашение планет переключаются по активной эре сразу, URL (`eraId`) обновляется только на остановке. Маркеры персонажей и подпись эры появляются при |t − t_эры| < 0.15 витка. Наклон камеры к диску — `smoothstep` по расстоянию до ближайшей остановки.

**Палитра.** Uniform `uEraColor` и `uEraGlow` в шейдерах галактики и нити, GSAP-твин к цвету активной эры за 0.8 с.

### 6.4 UI

**EntityCard.** Телефон: bottom sheet, `position: fixed`, `max-height: 55dvh`, `padding-bottom: env(safe-area-inset-bottom)`. Десктоп (≥ 900 px): правая панель 400 px, сосед контейнера `Canvas` с `z-index` выше оверлея `ScrollControls`, галактика слева остаётся интерактивной. Карточка к 3D-объекту не привязана никогда. Шапка: русское имя, оригинал в скобках, при `book.name` — «· в книге — Байта Дарелл». Над `body` — запись `timeline` активной эры, если есть. Теги: сезоны, части книг, эры. Кнопка «Показать на карте» (в «Хронике» и «Списке»).

| `book.presence` | Вкладки |
|---|---|
| `same` | «Сериал» (`body`), «Связи» |
| `different` | «Сериал» (`body`), «В книге» (`book.diff`), «Связи» |
| `show-only` | «Сериал» (`body`), «Связи»; бейдж «В книге нет» |
| `book-only` | «В книге» (`body`), «Связи»; бейдж «В сериале нет» |

Жесты: тело карточки — `overscroll-behavior: contain; touch-action: pan-y`; на телефоне при открытой карточке скролл-элемент нити получает `overflow-y: hidden` и `touch-action: pinch-zoom` (`ScrollControls` остаётся включённым, чтобы программные перелёты работали), чтобы жест мимо карточки не двигал нить; свайп вниз закрывает карточку, только если её контент проскроллен в начало.

**Hover-лейбл** — единственный HTML-якорь в 3D: имя + `summary` над объектом под курсором на десктопе, drei `<Html>` без `occlude`. На телефоне hover-лейбла нет.

**EraNav** — чипы эр, активная подсвечена цветом эры. **ModeToggle** — «Хроника / Карта / Список». **SpoilerBanner** — один раз, закрывается, запоминается в `localStorage`.

**Loading.** HTML-оболочка и постер (WebP) сразу. 3D-чанк — динамический `import()` после `load` на всех устройствах, кроме `navigator.connection?.saveData === true` и `prefers-reduced-motion` — там только по кнопке. Кнопка «Открыть 3D-карту» на постере видна до первого 3D-кадра и просто форсирует импорт. Проверка WebGL2 делается в оболочке до `import()`, чтобы телефон без WebGL2 не качал чанк.

### 6.5 Производительность

**Тиры.** Выбираются до монтирования `<Canvas>` (antialias и режим контекста после создания не меняются): `mid` — `matchMedia('(pointer: coarse)').matches || navigator.maxTouchPoints > 1` (телефоны и все iPad, ширина не участвует); `low` — `navigator.deviceMemory ≤ 2` или средний frame time первых 60 отрисованных кадров > 20 мс (понижаем пересозданием `<Canvas key={tier}>`, никогда не повышаем; позиция нити при пересоздании сохраняется: `CameraRig` пишет последний offset вместе с эрой из URL и на монтировании возвращает его мгновенно, если эра в URL с тех пор не менялась); `high` — остальное. Раскладка (bottom sheet против правой панели) — отдельный переключатель по ширине окна ≥ 900 px, пересчитывается на `resize` и поворот, тир при этом не меняется.

| Параметр | low | mid | high |
|---|---|---|---|
| `dpr` | 1 | ≤ 1.5 | ≤ 2 |
| Точек галактики | 40k | 60–80k | 150–200k |
| Пыль | 5k | 10k | 20k |
| MSAA | выкл | выкл | вкл |
| Постпроцесс | нет | нет | нет в v1 (bloom в половинном разрешении — v1.1) |
| `frameloop` | `demand` | `demand` | `demand` |

**Правила render-on-demand.**
1. Сами инвалидируют (по исходникам drei 10.7): `ScrollControls`, `CameraControls`, `Text`; изменение React-пропсов объектов сцены инвалидирует R3F сам.
2. Всё остальное анимируется через GSAP-твины, каждый с `invalidate()` в `onUpdate` (обёртка `tweenTo`). Глобальный `gsap.ticker.add(invalidate)` не используем: тикер GSAP держит свой rAF, пока есть слушатели, и кадры шли бы постоянно. Лерпы uniform — `gsap.to` по месту на общем `THREE.Color`, не ручной lerp в `useFrame`.
3. `uTime` галактики: `useFrame((_, delta) => { uTime.value += Math.min(delta, 1/30) })` — R3F не клампит delta, после простоя первый кадр приносит секунды. Вращение живёт только в отрисованных кадрах.
4. Пауза на `document.hidden`. Все анимации через delta-time: при 30 fps в режиме энергосбережения ничего не ломается.

**Бюджеты загрузки (gzip).** Оболочка ≤ 100 КБ; 3D-чанк ≤ 420 КБ (three 185 + fiber 57 + troika ≈ 50 + camera-controls 10 + gsap 27 + drei-компоненты ≈ 10; 300 КБ из ресёрча — оценка для vanilla без React); шрифт ≤ 150 КБ; `foundation.json` ≤ 150 КБ. Контроль: `rollup-plugin-visualizer` при сборке и `size-limit` в CI, падение при превышении. Если чанк вылезает — первым уходит gsap (переходы делает camera-controls, лерпы через `useFrame` с ручным `invalidate`), затем лишние drei-компоненты.

Текстур почти нет (планеты процедурные), суммарно GPU-текстур ≤ 16 МБ.

### 6.6 Ошибки

| Ситуация | Поведение |
|---|---|
| Нет WebGL2 (`canvas.getContext('webgl2') === null`, проверка в оболочке до `import()`) | Сразу «Список», ModeToggle скрыт, строка «3D недоступно на этом устройстве», чанк не качаем; `<Canvas fallback={<ListView/>}>` как страховка |
| `prefers-reduced-motion: reduce` | По умолчанию «Список», ModeToggle виден; в 3D переходы мгновенные (`smoothTime = 0`, GSAP `duration: 0`), вращение галактики выключено |
| Ошибка `import()` 3D-чанка | «Список», кнопка «Повторить загрузку 3D» (перезагружает страницу: браузер кэширует провал импорта модуля на время жизни документа; состояние живёт в URL) |
| `webglcontextlost` | Сцена снимается, «Список», кнопка «Перезапустить 3D» |
| Не загрузился `foundation.json` | Сообщение с кнопкой «Повторить», ничего больше не рендерим |
| Неизвестный маршрут или несуществующий id | Первая эра, «Хроника», тост «Такой страницы нет» |
| Битые данные (ссылка на несуществующий id, поле не по схеме, эры пересекаются) | Падает `build-data` на CI, до пользователя не доходит |

## 7. Тестирование

- **vitest, обязательные:** схема и проверки 5.3 проходят на всём `content/`; `derive.ts` — чистые функции, тесты на известные входы; `buildGalaxy(seed, count)` детерминирована (одинаковый сид — побайтно одинаковый буфер); `t` эр монотонен по `order`; `router/hash.ts` парсит и собирает маршруты симметрично, неизвестные маршруты уходят в дефолт.
- **Playwright smoke:** без 3D (`?no3d`) — список и пометка; «Список» рендерит все эры; карточка и история; на десктопе «Хроника» поднимает canvas и рисует кадры (`?debug` показывает draw calls ≤ 31), смена эры по хэшу в первую секунду не теряется; на телефоне открытая карточка блокирует скролл нити.
- **Ручной чеклист на iPhone** перед публикацией: скролл нити плавный, тап по планете открывает карточку, «Показать на карте» подлетает, батарея не греется за 5 минут, поворот экрана не ломает раскладку, Low Power Mode не ломает анимации, в Network нет запросов к внешним CDN за шрифтами.
- Чистые модули (`derive`, `schema`, `router`, `build-data`) пишутся через TDD. Компоненты сцены проверяются глазами и Playwright-скриншотом, не юнит-тестами.

## 8. Сборка и деплой

- `vite.config.ts`: `base: '/foundation/'`.
- `npm run build` = `vitest run && tsx scripts/build-data.ts && vite build && size-limit` — тесты, валидация данных и бюджет гоняются в том же CI, что и деплой.
- Монорепо `lab/scripts/build.sh` видит `package.json`, делает `npm ci && npm run build` и кладёт `dist/` в `_site/foundation/`. Ничего в workflow менять не нужно.
- После публикации v1 запись в `experiments.json` меняется на `status: done`.

## 9. Визуальное направление

Тёмная сцена, почти чёрный фон с синим отливом. Один акцент на экран — цвет активной эры. Шрифт Inter, текст в карточке ≥ 16 px, заголовок 22–24 px. UI-хром минимальный: чипы эр, переключатель режима, одна карточка. Никаких стеклянных панелей поверх всей сцены, никаких 20 плавающих подписей.

## 10. Границы v1

Не делаем: фильтр спойлеров, английский интерфейс (данные готовы), статические SEO-страницы на сущность, WebGPU, bloom на телефоне, поиск, картинки, звук, аккаунты, точную датировку до серии, снап-секции скролла сверх дотягивания из 6.3.

## 11. Этапы

1. **v0 без 3D** — проект в `foundation/`, схема, `build-data`, роутер, «Список», карточка, 5 эр и 5 планет заглушками, деплой в лабу. TDD. 1 день.
2. **3D** — галактика, планеты, нить, маркеры, «Хроника» и «Карта», переходы камеры, тиры. 2–3 дня.
3. **Контент** — ~125 карточек агентами по отдельному плану (число агентов и объём согласуются до запуска), верификация структурных фактов, ревью владельца. 1–2 дня; можно параллельно с этапом 2.
4. **Полировка** — карточки на реальных данных, ракурсы остановок, чеклист на iPhone. 1 день.
5. **Публикация** — витрина «готово». 1 час.
